# Altzavod / Altfactory

Одностраничный сайт концертной площадки в Твери. Next.js App Router, React, TypeScript, Tailwind CSS. Статический экспорт в `out/`; сервер, база данных и формы сбора персональных данных отсутствуют.

## Запуск

Нужны Node.js 22 LTS или новее и npm. После генерации проекта:

```powershell
cd altzavod-site
npm install
npm run dev
```

Проверка и сборка:

```powershell
npm run lint
npm run typecheck
npm run build
```

`next/font/google` получает бесплатные шрифты с кириллицей во время сборки и размещает их локально. Поэтому первая сборка требует доступа к Google Fonts; посетитель не обращается к Google за шрифтами.

## Контент и стартовые заглушки

Все тексты, афиша, контакты, ссылки, юридические слоты и настройки билетного оператора находятся в `src/data/site.ts`. По умолчанию `site.showsSection.mode` равен `placeholder`: показывается заглушка афиши. `demo` показывает карточки с явной демонстрационной пометкой, `live` предназначен для подтверждённых событий. Пустой массив `site.shows` всегда возвращает заглушку. Демо-события не являются реальными анонсами. Вместимость, оснащение, фотографии, контакты, реквизиты и документы нужно подтвердить у владельца площадки. Не указывайте вымышленные действующие контакты: заполните предусмотренные слоты.

Основной канал площадки — [Telegram](https://t.me/altzavod); ссылка хранится в `site.contacts.telegram.href`. Все детали посещения публикуются там. При смене официального канала обновите это поле; при `null` показывается неактивная кнопка. Дополнительные способы связи задаются в `site.contacts.other`: отображаются только записи с заполненным `href`, остальные скрыты. Для почты используйте `mailto:`, для телефона — `tel:`, для внешних каналов — настоящие HTTPS-ссылки.

Шапка и футер используют единый массив `site.navigation` с разделами «Афиша», «О площадке» и «Контакты»; ссылки ведут к `#shows`, `#venue` и `#contacts`.

Юридические документы до заполнения сохраняют пометки-заглушки. SVG в `public/images/` служат графическими плейсхолдерами, а не фотографиями площадки.

## Билеты

`site.tickets.provider` выбирает `demo`, `qtickets`, `ticketscloud`, `yandex` или `timepad`. В демо-режиме покупка и списание денег невозможны. Для подключения реального оператора задайте полученный у него HTTPS URL встраивания в `site.tickets.embedUrl` (или `embedUrl` отдельного события) и ссылку на оферту в `site.tickets.offerUrl`. При необходимости добавьте предоставленный оператором HTTPS URL скрипта в `site.tickets.scriptUrl`; проверьте официальную инструкцию и работоспособность на основном домене. Проект не выдумывает идентификаторы событий или SDK операторов. Если оператор требует дополнительный контейнер или атрибуты, адаптируйте `TicketWidgetModal.tsx` по его документации.

Внешний код виджета загружается только после открытия билетов. Оплата через СБП и карты РФ обеспечивается выбранным оператором и договором с ним; сайт сам платежи и персональные данные не обрабатывает. Не вставляйте секретные API-ключи в клиентский конфиг.

## GitHub Pages

1. Создайте репозиторий и загрузите файлы проекта в ветку `main`. После `npm install` сохраните созданный `package-lock.json` для воспроизводимых установок.
2. В Settings → Pages выберите Source: **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` выполнит `npm ci`, lint, генерацию типов Next.js, typecheck и статический экспорт. Pull request запускает только проверки; push в `main` или ручной запуск из `main` публикует `out/` после настройки Pages.

Для приватного репозитория GitHub Pages требует подходящего платного тарифа GitHub. Доступность публикации проверьте в Settings → Pages; для настройки Source выберите GitHub Actions.

`actions/configure-pages` определяет путь GitHub Pages: `/имя-репозитория` для проектного сайта и пустой путь для `owner.github.io` / настроенного собственного домена. При необходимости задайте переменную репозитория `NEXT_PUBLIC_BASE_PATH`; значение `/` явно включает корень домена. Переменная влияет на сборку, поэтому после изменения нужен новый деплой.

Для локальной проверки подпапки в PowerShell:

```powershell
$env:NEXT_PUBLIC_BASE_PATH = '/altzavod-site'
npm run build
Remove-Item Env:NEXT_PUBLIC_BASE_PATH
```

Для переноса на основной домен очистите `NEXT_PUBLIC_BASE_PATH` (или задайте `/`), пересоберите сайт и загрузите содержимое `out/` в корень хостинга. Настройте домен и HTTPS у хостера. Все локальные изображения и иконки проходят через `assetPath(...)`; ресурсы Next получают тот же префикс автоматически. `.nojekyll` сохраняет каталог `_next` на GitHub Pages.

## Производительность и доступность

Визуальный стиль сочетает скруглённые поверхности Material 3 с интерьером завода: угольно-чёрный фон, стальные нейтральные оттенки, белый текст и глубокий красный акцент. Заголовки используют Unbounded 700–900, основной текст — Manrope, технические подписи — JetBrains Mono; все три шрифта подключены через next/font/google с кириллицей и латиницей. Статичный SVG-паттерн зерна и мягкие дымчатые и бордовые градиенты не требуют анимации фильтров. Кнопки и небольшие карточки используют плотные тональные поверхности. Блюр крупных секций и затемнения билетов включён только на десктопе; шапка имеет лёгкую матовую подложку. CSS-тикер работает на всех ширинах и при prefers-reduced-motion движется втрое медленнее.

Сайт автоматически выбирает тёмную или светлую палитру по системной настройке. Компактная кнопка в шапке переключает режимы «Авто → Светлая → Тёмная»; ручной выбор хранится в `localStorage` под ключом `altzavod-theme`, а «Авто» удаляет переопределение и реагирует на изменения системы. Ранний скрипт в `layout.tsx` задаёт `data-theme` и `data-theme-mode` до отображения страницы, без серверного запроса и вспышки другой темы. Светлая палитра использует тёплый бетонно-бумажный фон, графитовый текст и глубокий красный акцент. Цвета, боковые поля, интервалы секций, размеры контролов и скругления находятся в `src/app/tokens.css`. На телефонах основные CTA первого экрана занимают полную ширину, на планшетах hero и контакты используют одну колонку. Контролы имеют область нажатия не меньше 44 px, иконки действий — 20 px. Единый `BrandMark` объединяет красную букву-колонку «А», трафаретный глаз с лучами и басовый динамик; знак используется в шапке, hero и футере. Угловые метки и штрихи повторяют его мотивы в секциях. Favicon и иллюстрации используют белый, серый и заводской красный. Билеты оформлены как винтажный бордовый ковёр с медальонами, розетками, широкой орнаментальной каймой и лёгкой тканой фактурой. SVG загружается через `assetPath` только при открытии окна; внутри него находится плотная контрастная панель, адаптированная к выбранной теме. Ковровый орнамент сохраняет собственные цвета, а текст, кнопки и бейджи остаются читаемыми без дополнительного мобильного blur. Реальный iframe оператора сохраняет собственный фон. Плотный красный hover кнопок слегка затемнён поверх базового `#ef4444`, чтобы белые подписи сохраняли контраст.

Появление блоков использует IntersectionObserver с резервной проверкой геометрии; анимации меняют только `transform` и `opacity`. `prefers-reduced-motion` упрощает переходы и убирает резкие смещения. Лёгкая оболочка билетов готова к первому нажатию, внешний код оператора загружается только внутри открытого окна. Диалог выдвигается снизу за 350 мс без масштабирования и закрывается за 250 мс; крестик остаётся вне внутреннего скроллера, учитываются safe-area и VisualViewport. Меню появляется за 300 мс с интервалом 50 мс между пунктами и закрывается за 200 мс. При reduced motion закрытие занимает 80 мс. Прокрутка к якорю начинается после закрытия меню и разблокировки страницы; сохраняются хеш, история и возможность прервать движение жестом. Меню и диалог используют общую блокировку прокрутки: на сенсорных мобильных экранах фиксируется body, а перед возвратом фокуса или переходом к якорю восстанавливается прежняя позиция. Высота cookie-баннера автоматически резервируется внизу футера. Шкала слоёв: фон — 0, контент — 10, cookies — 30, шапка и её меню — 40, диалог — 50. Согласие на необязательное локальное хранение хранится в `localStorage`; аналитика и рекламные трекеры не подключены.

Перед публикацией заполните реальные юридические сведения и документы, подтвердите информацию о площадке и подключите настоящий билетный виджет. Стартовый шаблон намеренно сохраняет демо-пометки.
